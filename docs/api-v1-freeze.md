# API 1.0 freeze policy

API **1.0** is the complete public baseline for the core contract and the theme host. The SDK toolkit is **1.0.0**, and the application is **0.1.0**. Core's `CONTRACT_VERSION` and `CONTRACT_MINOR` are the sole authority for the API version. Desktop derives the same version from the pinned schema. SDK package major and minor match the API. The application and database are versioned independently.

## Frozen contents

The only frozen set is `crates/core/tests/golden/v1.0/`. It consists of 305 current message examples plus the original bytes of `contract.schema.json`, for 306 files in all. `frozen_manifest.rs` independently pins the SHA-256 of the original bytes of every file, in stable UTF-8 relative path order. Ordinary tests are read-only. Never run generators to repair frozen digests. The set of `v*` directories in the frozen root must match `FROZEN_SETS` exactly.

The [schema](contract.schema.json) defines message structure, and the [guarantees](../crates/core/src/guarantees.md) define semantics. The five message roots share `$defs`. Type and field names, defaults, nullability, command policy, and limits are part of the contract. `Snapshot.features` lists actual capabilities. API minor alone cannot establish platform or device support.

## Compatibility rules

- Requests and queries reject unknown fields, unknown variants, and invalid values. Execute input only when fully understood. Interpret omission, `null`, and empty collections according to each field's specification.
- Results and events tolerate future fields. Unknown string enum values normalize to `unknown`, and unknown tagged variants normalize to `{type:"unknown"}`. ErrorCode is open and ErrorKind is closed. User dictionaries retain their original values.
- At the same minor, the normalized schema shape and the actual set of Snapshot features must each match. Bump the shared minor before adding fields, messages, enum values, or capabilities, even for a desktop-only host interface.
- After bumping the minor, allow only compatible growth. Preserve existing types, fields, and variants. Do not tighten inputs, make required outputs optional, change scalar types, formats, or defaults, or reduce limits. Command `x-class` and `x-local-path` and error code `x-kind` cannot change or disappear. `x-origins` cannot be tightened. ErrorKind cannot gain members even with a minor bump. Never decrease the minor.
- Both full and field-by-field comparisons ignore `description`, `title`, `$comment`, and `x-risk` annotations while retaining business fields of the same names. Equivalent singleton `allOf` and string enum groupings and ordering can be normalized. Changes to descriptions still require human review and cannot change semantics.
- For types used as both input and output, apply both sets of rules. Relaxing a required field may break output guarantees, so the guard conservatively rejects it. If the toolchain emits an equivalent schema, explain the change and improve normalization and mutation self-tests. Preserve frozen files.

Frozen messages must still decode, retain their values, and validate against the current schema. The frozen manifest, byte digests, field and message growth checks, metadata, error classification, and feature guards must all pass, including their mutation self-tests. Review semantics, permissions, safety, ordering, undo, resource lifetimes, and durability separately from schema tests.

## Explicit generation and future releases

Leave all `UPDATE_*` variables unset in ordinary tests and CI. Even setting one to `0` triggers writes. Maintainers generate current and the schema only in the environment of an explicit command.

```sh
UPDATE_SCHEMA=1 cargo test --offline -p mpmp-core --lib contract::tests::exported_schema_is_up_to_date
UPDATE_GOLDEN=1 cargo test --offline -p mpmp-core --test contract_golden golden_files_are_up_to_date
```

After updating desktop's pinned core snapshot, run `npm run gen:types --prefix apps/desktop/sdk` from the desktop repository root.

The first public reset created a new `v1.0` from the verified current examples and schema. That one-time authorization has ended. Keep its files and digests intact. For API 1.1, add v1.1 and its manifest entry while preserving v1.0 bytes and digests. Run all guards and mutation self-tests with the update variables unset. Breaking changes require a new major and an independent frozen set. Keep existing sets until support for that major is explicitly withdrawn. Maintainers create release tags. A directory name alone provides no evidence that a tag exists.

The desktop vendor tree and `core-contract.lock.json` are generated by the export and update tools. They pin the actual core revision, API version, and file digests. Use the tools instead of editing them in the monorepo. The database and other persistence formats are versioned independently of the API. An API minor bump does not automatically relabel or migrate them.
